# 许可证整理与分发

不要求将所有许可证拼接进根 LICENSE，也不要求逐个列出内部类、函数或模块。根 LICENSE 声明自有代码许可；THIRD_PARTY_NOTICES.md 汇总第三方作品及归属，各组件保留适用的原始声明。

应按实际分发内容及其条款处理：

- **随仓库分发的第三方源码**：保留版权、LICENSE、适用的 NOTICE 和文件头。复制少量代码也可能需要保留声明。一个库可统一列举，不必每个文件重复放相同许可证。
- **只声明外部依赖，让用户自行安装**：通常无需为此将每个依赖的许可证全文复制到源码仓库。建议列出依赖；派生关系、链接方式及 GPL 等条款仍需分别判断。
- **随 UI.exe、DLL、Python 环境或网盘包分发的组件**：按实际携带的组件（含传递依赖）附所需许可与归属。只在 GitHub 上贴链接不能替代下载包应附的声明。vcpkg 的 installed/<triplet>/share/<port>/copyright 可作为整理入口，不能代替对整个发行包的核查。GPL/LGPL 组件还可能要求提供对应源码、修改说明或允许重新链接，只有 LICENSE 未必足够。
- **模型权重及数据集**：与代码分别核对对应模型卡及数据许可。
- **仅提供外部下载链接、不分发该作品**：通常不必为链接本身附许可证全文；应指向官方说明，准确说明适用限制。

MIT 要求随副本或实质部分保留版权与许可声明。Apache-2.0 第 4 条要求提供许可证、保留相关声明、标明修改，并在上游带有 NOTICE 时按条款保留相应归属。具体义务以适用条款为准。

参考：[Apache-2.0 原文](https://www.apache.org/licenses/LICENSE-2.0)、[MoGe MIT 与内置组件原文](https://github.com/microsoft/MoGe/blob/main/LICENSE)、[本项目 GPL-3.0 原文](../LICENSE)。
